## 它解决什么问题

科研入门最难的从来不是"找不到资料"，而是三件事没人告诉你：

1. **我的方向到底是什么？** 只知道自己对"人工智能"感兴趣，但人工智能底下有几十个子方向，选哪个？
2. **我现在会什么？** 学过一门课、写过一段代码，不等于掌握了对应的知识点。自评往往不准。
3. **接下来该学什么？** 网上的路线图是给所有人看的，不是给我的。

市面上的学习路线工具，绝大多数让你填一张自评问卷，然后吐出一份通用的课表。**问题在于：自评不可靠，通用路线不通用。**

我们换了个做法。

## 核心能力

### 1. 从项目代码反推能力（差异化最强）

不问你"会不会 PyTorch"，而是让你**粘贴一段自己写过的代码**。系统从中找出真实存在的证据，反推出你可能掌握的知识点，并且每一条都给出：

- **证据**——引用代码里具体的位置或写法
- **推断**——据此判断你掌握了什么
- **置信度**——从 0.9（代码中有明确直接证据）到 0.6 以下（仅弱信号）

> 关键设计：**只依据代码里真实存在的证据。** 不会因为"做图像分类一般会用到 CNN"就推断你会 CNN。  
> 置信度偏低的项会被单独列出，主动请你确认，而不是直接下结论入库。

### 2. 分层知识库与能力画像

知识结构分五级：**分类 → 子学科 → 课程 → 单元 → 知识点**。

掌握状态挂在最细的"知识点"上，上层状态由下层聚合计算得出，避免层层手工维护导致的不一致。

| 一级分类 | 回答的问题        |
| ---- | ------------ |
| 数学基础 | 这门方向需要哪些数学   |
| 编程基础 | 语言与工程能力      |
| 理论基础 | 算法、架构、领域知识   |
| 工具基础 | 框架、库、工程工具    |
| 科研素养 | 论文阅读、实验设计、写作 |

### 3. 按缺口定制的学习路线

不讲"本科生走基础路线、研究生走研究路线"，而是**按缺口分**：

| 计划形态 | 适用         | 知识线 : 论文线 |
| ---- | ---------- | --------- |
| 基础型  | 前置缺口大，想系统补 | 80 : 20   |
| 混合型  | 有基础，想尽快上手  | 50 : 50   |
| 研究型  | 前置扎实，目标做研究 | 25 : 75   |

一个基础扎实的本科生完全可以直接读论文，一个跨专业的博士生很可能需要补数学——**按缺口分，不按身份分**。

计划不是一段聊天记录，而是**一张可读的每日路线页面**：顶部是目标与整体期限，中间是进度条与阶段时间轴，下面是每一天的卡片 —— 当天要完成什么、为什么排在这一天、属于哪个知识点、预计投入多久。勾掉一天进度实时更新；计划逐阶段展开，**已勾选的状态不会被下一次展开冲掉**。

> 每天必须写**可验证的产出**。"读 6.2 节"是过程，"能套用两个不等式"才是结果 —— 只有结果能被检验，计划才真的可执行。

## 它是怎么工作的

```
用户自然语言（不需要选模式 —— 用哪种能力由 AI 自己判断）
   ↓
方向模糊？  → 选项式追问，2–3 轮内收敛到具体方向
有代码？    → 从代码里的真实证据反推能力（证据 · 推断 · 置信度）
要计划？    → 问齐目标 / 期限 / 可投入时间，先出阶段骨架
   ↓
确认骨架 → 逐阶段展开到天，渲染成可读的每日路线页面
   ↓
持续演进（论文推送 · 勾选回写进度）
```

**一条贯穿全程的原则**：

> **结构归开发者，内容归 AI。**  
> 结构由开发者定死，AI 只负责填值、提议结构变更、给出证据与置信度。  
> 所有写入都走「草案 → 预览 → 用户确认 → 落库」，**AI 没有直接改知识库的权限。**

## 快速开始

### 跑 Web 版

**已经部署好了，直接用**：`https://academic-nav-82s.pages.dev`

要自己重新部署（需要 Cloudflare 账号 + 一个模型 API Key）：

```bash
cd web-demo

# 1. 把两个密钥写进 .env（该文件已在 .gitignore 里，不会被提交）
#      CLOUDFLARE_API_TOKEN=...   dash.cloudflare.com/profile/api-tokens，用 "Edit Cloudflare Workers" 模板
#      MODEL_API_KEY=...          platform.deepseek.com/api_keys

# 2. 把模型 Key 设成 Pages 的加密变量（只需做一次）
npx wrangler pages secret put MODEL_API_KEY --project-name=academic-nav

# 3. 校验提示词一致性 → 组装 dist/ → 部署
npm run deploy
```

> **改了环境变量之后必须重新部署一次才生效。** Cloudflare Pages、Vercel、Netlify 都是这个规矩。

三条自检命令，遇到问题先跑它们：

```bash
node web-demo/scripts/check-prompts.mjs      # 提示词两边是否逐字一致
node web-demo/scripts/check-cloudflare.mjs   # Token / Pages 密钥 / 线上实测，三步定位
npm test --prefix web-demo                   # 云函数 33 项 + 前端 45 项断言
```

完整说明见 [`web-demo/README.md`](web-demo/README.md)。

> **为什么部署在 Cloudflare Pages 而不是 Workers？**
> `*.workers.dev` 在国内被 DNS 污染，并且 TLS 握手时看到这个域名就被阻断
> （同一个 Cloudflare IP，SNI 换成别的域名立刻正常）。
> 而 `*.pages.dev` 国内直连可用，同样能跑服务端代码，页面与 API 还同域，连 CORS 都不用配。

## 技术方案

| 层   | 选型                                    | 为什么                  |
| --- | ------------------------------------- | -------------------- |
| 前端  | 单文件 HTML，零外部依赖                        | 可直接托管到任何静态空间，无构建步骤   |
| 服务端 | Cloudflare Workers（边缘函数）              | 邮箱注册即可，无需实名；有免费额度    |
| 模型  | OpenAI 兼容接口（DeepSeek / 智谱 / Moonshot） | 换服务商只改两个环境变量，代码不动    |
| 密钥  | 只存在服务端环境变量                            | 查看页面源码也拿不到，前端只认识函数地址 |

**安全设计**：密钥不下发前端 · 单条消息截断 24000 字符 · 只取最近 12 轮上下文 · CORS 由环境变量控制。
