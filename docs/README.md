## 关于"部分有效"

项目在第 5 份文档处经历了一次**交付形态的转向**：从"自建 Web 全栈应用"改为"LearnBuddy 专家智能体 + 极简公网页面"。

转向后，以下内容仍然有效：

- **数据模型**（知识库分层、领域树、Plan/Stage/PlanItem）—— 只是载体从 Prisma 换成了资料库数据表
- **11 个 skill 及其统一契约** —— 落到了 `expert/` 的 SKILL.md 与 `prompts/` 目录
- **ChangeSet 变更确认机制** —— 作为设计原则保留
- **五阶段主流程与三类上下文** —— 平台原生提供，无需自己实现

以下内容已作废：

- Next.js 全栈技术栈、17 个 API 契约、`lib/llm.ts` 封装
- 所有部署方案（Vercel / Cloudflare / 国内云厂商 / ICP 备案）—— 在线链接改由平台「资料库」提供

## 为什么保留作废的文档

因为这**恰好是这个作品想证明的事**：它不是一个方案想清楚再动手的项目，而是在推演中不断修正、最终收敛的项目。

每一次转向都留下了记录。对评委来说，这比一份"从头到尾都很顺"的方案更有说服力。
