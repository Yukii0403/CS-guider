## 6. 附录：编程工程组 12 个专家的场景对照（2026-09-17 补）

### 6.1 先纠正一个理解：这 12 个不是 12 个选项

它们是**开发流程上不同环节的工具**，彼此不替代。先用这一层判断该找谁：

| 层 | 环节 | 专家 |
|---|---|---|
| L0 | 方法论：怎么用 AI 写代码 | `SuperpowersZh` |
| L1 | 架构：想清楚系统长什么样 | `SoftwareArchitect` |
| L2 | 原型 / MVP：先跑通一个能看的东西 | `RapidPrototypingEngineer`、`MvpDevExpertTeam` |
| L3 | 编码：真正写（按技术栈切，**只选一个**） | `Frontend`、`PythonFullstackEngineer`、`DesignToCodeExpert`、`EdgeoneMakersExperts` |
| L4 | 质检与收尾 | `CodeReviewExpert`、`GitWorkflowExpert`、`HskDevopsExpert` |
| L5 | 横切：提示词本身 | `PromptEngineer` |

### 6.2 逐个场景

#### L0 · 方法论

**`SuperpowersZh` · AI 编程方法论专家**（agent 型）
- 声明的能力：20 项 AI 编程方法论，覆盖**头脑风暴、测试驱动开发、系统化调试、代码审查**，适配中文文档与国内平台规范
- ✅ **什么时候用**：① 动手写代码前，先让它带你把需求拆成设计规格；② **卡在一个 bug 上超过半小时**，让它按"系统化调试"找根因再修；③ 按国内团队风格做代码审查
- ❌ **什么时候别用**：不要指望它替你产出产品代码——它是教练，不是施工队
- 👉 **对你们**：**优先级最高**。你们"基础弱 + 全靠 AI Coding"，短板恰恰不是"AI 不会写"，而是"你们不知道怎么指挥 AI 写"。它教的正是这个

#### L1 · 架构

**`SoftwareArchitect` · 架构通**（agent 型）
- 声明的能力：全局架构设计、可扩展高可用、**架构演进与重构路线图**、评审架构方案并输出设计文档
- ✅ **什么时候用**：系统规模真的上来了（多服务、有并发、要长期演进），或要评审一份已有架构方案
- ❌ **什么时候别用**：它的原始假设是"**大型软件系统 + 长期发展规划**"。你们是 10 天、2 人、单仓库的小 demo
- 👉 **对你们**：**基本用不上，而且有反作用**。用了它容易把需求放大成"大型系统设计"，多出文档和抽象层，直接拖掉两三天。你们需要的架构决策（单文件 HTML + 云函数 + 数据表）已经定了

#### L2 · 原型 / MVP

**`RapidPrototypingEngineer` · 闪造造**（agent 型，OPC）
- 声明的能力：以**极快速度**把创意变成**可工作的原型**；低代码工具加速开发
- ✅ **什么时候用**：只想验证"这个交互能不能成立"，不在乎工程结构，原型可以随时丢掉
- ❌ **什么时候别用**：已经过了验证期、要往交付形态收敛的时候
- 👉 **对你们**：**已经过了这个阶段**。`web-demo/` 就是原型的产物，且比"随便跑跑的原型"扎实得多。除非想快速试一个全新交互点子，否则不用

**`MvpDevExpertTeam` · MVP 开发专家团**（★ **team 型**，8 位专家）
- 声明的能力：**调研 → 设计 → 编码 → 测试 → 部署全流程协作**，快速开发 MVP 产品
- ✅ **什么时候用**：你想"从零做一个完整产品"，并且愿意**把流程主导权交出去**，让 8 个角色自己分工推进（它的默认输入是"我想从零做一个团队协作工具""帮我开发一个电商小程序"）
- ❌ **什么时候别用**：你已经有明确形态、明确技术栈、明确进度表的时候
- 👉 **对你们**：**不建议**。两个原因——① 你们的产品形态（专家包 + 提示词）跟它假设的"从零做个应用"不重合；② 它是 team 型，会**接管编排**，和你们现在"自己掌舵 + 让 AI 执行单个任务"的节奏冲突

> **team 型 vs agent 型的根本差别**（选这类专家前必读）：
> - **agent 型**：你主导，它配合。你给一个具体任务，它做完交回。
> - **team 型**：它主导，你给目标。它自己拆解、自己分工、自己推进。
> 你们现在最缺的是"每一步都能自己判断对不对"，所以现阶段应该优先用 agent 型。

#### L3 · 编码（按技术栈切，**只选一个**）

**`Frontend` · 前端界面开发专家**（agent 型）
- 声明的能力：精通响应式界面，移动优先与可访问性，用鲜明排版与色彩构建**落地页、仪表盘、表单**等高保真界面；标签含 React / Next.js
- ✅ **什么时候用**：要做页面视觉与交互，尤其是仪表盘、表单这类"信息密度高"的界面
- 👉 **对你们**：**部分匹配**。你们的 `index.html` 确实是手写前端，界面打磨可以借它；但它默认是 React/Next.js 栈，你们是**单文件原生 HTML/CSS/JS、零依赖**——别被它带去上构建工具，那会破坏"单文件可托管"这个刻意的设计

**`PythonFullstackEngineer` · Python 全栈工程师**（agent 型）
- 声明的能力：后端 API（FastAPI + Pydantic v2、分层架构）、数据分析（Pandas/Polars/Plotly）、**带类型注解和 pytest 的自动化脚本**、爬虫
- ✅ **什么时候用**：写后端服务、数据处理、爬虫、以及**要配 pytest 的脚本**
- 👉 **对你们**：**部分匹配，但有一块正好**。你们的主栈是 JS（Cloudflare Workers），不需要它的后端能力；但专家包里那几个脚本（`dedupe.py`、`render_domain_tree.py`）正属于"要配测试的 Python 脚本"——想给脚本补 pytest 时找它

**`DesignToCodeExpert` · 图变码**（agent 型，分类在产品设计）
- 声明的能力：Figma 设计稿和**截图**转成可直接用的代码组件，内置无障碍支持
- ✅ **什么时候用**：手上已有设计稿或参考截图，要还原成页面
- 👉 **对你们**：**用不上**——你们没有设计师、也没有设计稿。唯一沾边的用法是：拿一张你们喜欢的别人家产品的截图，让它还原成 HTML 作参考

**`EdgeoneMakersExperts` · Makers 开发专家团**（★ **team 型**）
- 声明的能力：在 **EdgeOne Makers** 上构建并部署 Web 应用——前端 + Serverless 后端 + **AI Agent 开发** + 部署到全球加速网络
- ✅ **什么时候用**：你的目标就是"开发一个能聊天的 AI 助手网站并部署上线"
- 👉 **对你们**：**值得认真看一眼**。它描述的东西和你们的 `web-demo/`（单页 + 云函数 + 模型接口）几乎是同一件事，只是平台换成腾讯云 EdgeOne。它是一条**替代部署路线**——如果 Cloudflare 那边不顺，或者你们想要"腾讯云生态"这个叙事，可以考虑切过去。但**别在 9/26 前 5 天换部署平台**

#### L4 · 质检与收尾

**`CodeReviewExpert` · 火眼眼**（agent 型）
- 声明的能力：鹰眼标准检查代码、**在缺陷到达生产前拦截**、识别性能瓶颈与潜在 Bug、制定规范与 Review 清单
- ✅ **什么时候用**：写完一个模块后、提交/部署前、以及要产出"代码质量"类材料时
- 👉 **对你们**：**优先级最高之一**。你们是新手 → **看不出来 AI 写的代码有没有坑**。这正是它存在的意义。建议固定成习惯：每次 AI 写完一段，先过一遍它

**`GitWorkflowExpert` · 分支通**（agent 型）
- 声明的能力：Git 高级工作流与分支策略、制定**代码合并和冲突解决规范**、搭建 Git Hook 与自动化检查
- ✅ **什么时候用**：多人并行开发、冲突频发、要搭 CI 的时候
- 👉 **对你们**：**优先级最低**。2 人、单仓库、一条 `main`、每天 pull→commit→push，冲突概率很低，搭 Git Hook 更是过度工程。**但有一个用法值得**：你们赛制上需要"逐日长出来"的提交历史作证据，可以让它帮你设计一个"每天该提交什么"的节奏——这属于方法层面，不是工具层面

**`HskDevopsExpert` · 贝锐花生壳**（agent 型）
- 声明的能力：基于 HSK CLI，提供**零配置公网预览、内网穿透、文件托管、项目部署**
- ✅ **什么时候用**：本地跑的东西要马上给别人（队友、评委）一个链接，又不想配正式部署
- 👉 **对你们**：**当应急兜底很好用**。但要说清一件事：它给的是"临时让本地服务被公网访问"，和赛事要求的"部署到浏览器环境、可直接访问的在线链接"**不完全是一回事**——正式提交还是走 Cloudflare Workers。它的价值在于：部署卡住时，演示不至于开天窗

#### L5 · 横切

**`PromptEngineer` · 提示词工程师**（agent 型）
- 声明的能力：系统提示词架构、思维链与少样本设计、**用测试数据驱动迭代**、把提示词优化到模型稳定输出；明确支持"**诊断现有提示词效果不佳的原因**"
- ✅ **什么时候用**：① 从零设计一个任务的系统提示词；② **手上已有提示词但效果不稳，想找原因**
- 👉 **对你们**：**优先级最高**。你们的**核心资产就是提示词**——`prompts/` 那 3 段正文 + 3 个 SKILL.md 的触发描述。而且它的第二条能力，正好对上你们 `analyze-project.md` 里自己写的那三条"待调优方向"。这是唯一一个直接作用在你们产品内核上的专家

### 6.3 ★ 对你们项目的取舍结论

| 判断 | 专家 | 理由 |
|---|---|---|
| **该用** | `PromptEngineer` | 唯一直击产品内核（提示词 + 触发描述） |
| **该用** | `CodeReviewExpert` | 新手看不出 AI 代码的坑，这是最实际的风险 |
| **该用** | `SuperpowersZh` | 教你们"怎么指挥 AI 写"，尤其**系统化调试**——报错看不懂是必然会发生的 |
| **按需** | `HskDevopsExpert` | 部署卡住时的应急公网链接兜底 |
| **可选（二选一）** | `EdgeoneMakersExperts` | 若想换腾讯云生态做"AI 助手网站"；**但别在最后 5 天换平台** |
| **可选（二选一）** | `MvpDevExpertTeam` | 若愿意把流程主导权交给专家团；与你们现在"自己掌舵"的节奏冲突 |
| **部分可用** | `Frontend` | 界面打磨可借；但别被带去上构建工具，单文件是刻意的设计 |
| **部分可用** | `PythonFullstackEngineer` | 只在给 `skills/scripts/*.py` 补 pytest 时用 |
| **暂不需要** | `RapidPrototypingEngineer` | 你们已经过了原型期 |
| **暂不需要** | `GitWorkflowExpert` | 2 人单仓库，冲突概率低 |
| **用不上，且有反作用** | `SoftwareArchitect` | 会把 10 天小 demo 放大成"大型系统设计"，拖掉两三天 |
| **用不上** | `DesignToCodeExpert` | 没有设计稿 |

### 6.4 一句话记住

> **别把它们当"选哪个更好"，要当"我现在卡在哪一步"。**
> 卡在"不知道该做什么"→ 找 L0/L1；卡在"写不出来"→ 找 L3；卡在"写完了不放心"→ 找 L4；
> 而你们的真正瓶颈在第 5 层——**提示词写得好不好，直接决定产品内核强不强**。
