## 1. 一句话定位

**从你已有的项目和代码里反推真实能力水平，据此生成可执行的学习路线，并按你的学习进度持续推送难度匹配的论文。**

## 2. 目标用户与场景

- **用户**：高校本科高年级 / 硕士 / 博士低年级，正在或准备进入某个科研细分方向
- **触发场景**：想切入一个方向（如图像识别、NLP），但说不清三件事 —— ①我缺什么 ②先学什么后学什么 ③现阶段该读哪些论文
- **现有方案的问题**：主流工具靠自评问卷（"你学过概率论吗"）判断水平，用户普遍高估或低估自己；论文推荐靠关键词和热度，与学生当前水平不匹配，推了也读不懂

## 3. 核心价值与差异化

| 维度 | 主流做法 | 本方案 |
|---|---|---|
| 能力从哪来 | 用户自评问卷 | AI 从项目 / 代码中抽取证据反推 |
| 能力如何表示 | 一次性标签 | 四层知识库，可逐级下探 |
| 路线怎么生成 | 固定模板 | AI 追问细化方向 → 生成草案 → 用户确认落库 |
| 论文怎么推荐 | 热度 / 关键词 | 与知识库节点 + 计划进度做难度匹配 |

**对外主打的一句话**：不问你学过什么，看你做过什么。

## 4. 功能范围

### P0 — 初赛必须做（缺任何一个，演示链路就不闭合）

**P0-1 项目导入与能力反推**
- 输入：项目描述 / README / 代码（初赛建议只支持「粘贴文本 + 上传 zip + GitHub 链接」中最容易实现的 1–2 种）
- AI 输出：证据列表（用了哪些库、实现了什么算法、涉及哪些数学）→ 推断的技能点 → 每条带置信度
- 用户确认 / 修正 → 写入知识库（**不允许 AI 直接入库**）
- 产出物：项目 → 技能点映射结果，可回看

**P0-2 知识库 + 能力地图**
- 四层结构：L1 能力分类 → L2 方向 → L3 课程 / 资源 → L4 章节 / 知识点
- 每个节点带：状态（未学 / 在学 / 已掌握）、置信度、证据来源、1–2 句给 AI 读的摘要
- 可视化：树图或能力地图（**用户可见**，这是把内部机制变成体验分的关键）
- 节点详情面板：能看到"AI 为什么认为我会这个"

**P0-3 对话式学习路线生成**
- AI 追问 → 逐步把模糊方向收敛到细分方向（人工智能 → 图像识别）
- 生成双轨计划：**知识基础线** + **论文阅读线**
- 每条任务关联到具体知识库节点 / 论文
- 草案 → diff 预览 → 用户确认 → 落库（也可更新已有计划）

**P0-4 计划可视化**
- 阶段 → 周 → 任务的时间轴或看板
- 任务状态可手动切换，状态变化回写知识库节点

**P0-5 论文按水平推送**
- 依据：知识库节点状态 + 计划当前进度
- 数据源：arXiv API（免费、无需 key），按分类拉取近期论文
- 每篇给 LLM 打：难度等级（1–5）+ 关联知识点 + 一句话"为什么推给你"
- 推送卡片：标题、摘要、难度、关联节点、推荐理由、原文链接
- 初赛触发方式：**手动点"刷新推荐"**，不必真做定时任务

### P1 — 有余力再做
- 进度打卡 → 自动回写知识库状态 → 影响下一轮论文推荐（体验闭环）
- 计划 / 能力画像导出（Markdown、PDF）
- 论文已读 / 收藏标记

### 明确不做（初赛）
- 多用户协作、权限体系、社交功能
- 论文全文解析（只做标题 + 摘要级）
- 全学科课程体系（只预置 2–3 个种子方向，其余由 AI 生成 + 用户确认）
- 复杂账号体系（初赛用本地存储 / 无登录）

## 5. 知识库 schema 草案（关键技术红线）

### 知识节点 KnowledgeNode
| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 稳定 ID，如 `math.probability.ch3` |
| parent_id | string \| null | 父节点，根节点为 null |
| level | 1–4 | 层级 |
| name | string | 节点名 |
| summary | string | 1–2 句，给 AI 读的描述 |
| domain | string | 领域标签，用于论文匹配 |
| status | enum | 未学 / 在学 / 已掌握 |
| confidence | 0–1 | 置信度 |
| evidence | array | `[{type: code\|course\|self_report, ref, detail}]` |
| source | enum | seed / ai_inferred / user_confirmed |
| updated_at | datetime | |

### 学习计划 LearningPlan
- `id`、`title`、`target_domain`、`status`
- `tracks`: `[{type: 知识基础\|论文阅读, items: [...]}]`
- item：`{id, title, node_id, paper_id?, start_date, end_date, status}`

### 论文 Paper
- `id`、`arxiv_id`、`title`、`abstract`、`url`、`published_at`
- `matched_nodes: [node_id]`、`difficulty: 1–5`、`reason`（为什么推给你）

### 四条技术红线（写进 PRD，开发时必须遵守）
1. **所有 AI 输出必须过 schema 校验**，失败重试 ≤3 次后降级到预置数据，绝不让格式漂移直接打到前端
2. **知识库写入一律走「草案 → diff → 用户确认 → 落库」**，AI 无直接写权限
3. **推断必须带 evidence + confidence**，禁止裸结论入库
4. **演示路径必须可脱离实时模型 / 网络**：预置一份完整 demo 数据，现场断网也能演完

## 6. 技术方案（轻量版）

| 层 | 选型建议 | 理由 |
|---|---|---|
| 前端 | React + Vite（或 Next.js） | 生态熟、部署简单 |
| 可视化 | ECharts（树图 / 雷达 / 时间轴） | 中文文档全，树图开箱可用 |
| 后端 | Python FastAPI | AI 生态顺，2 人好分工 |
| 存储 | SQLite | 零运维，够用 |
| 模型 | LearnBuddy 平台 / 可配置 API | 顺带积累对话记录 |
| 结构化输出 | JSON Schema 校验 + 重试 | 红线 1 的落地手段 |
| 论文数据 | arXiv API | 免费、无需 key |
| 部署 | Vercel / 静态托管 + 后端服务 | 要给出在线可访问链接 |
| 仓库 | GitHub + LICENSE（MIT / Apache 2.0） | 方向二必须开源 |
