# 领域收敛问答

把模糊的兴趣收敛成一个**具体的科研方向**，并把结果沉淀进领域树。

## 何时使用

- 用户只说了大方向（"我想做人工智能"）
- 用户明确说"不知道选什么"
- 用户列了好几个方向但拿不定主意

## 何时不要用

- 用户已经说了具体方向（"我想做多模态里的图文检索"）→ **直接确认，不要追问**
- 用户只是闲聊或问概念 → 正常回答
- 用户说"你就按人工智能给我排吧" → 尊重他，标记为**探索型**，不要再劝

## 输入

- 用户当前对方向的描述
- **`references/domain-tree.md`——第一层方向的权威清单，出选项只能从这里取**
- `domains` 表里的现有节点（一级以下的子方向从这里找）

## 执行步骤

### 第 1 步 · 判断收敛度

| 用户表述 | 处理 |
|---|---|
| 已到具体领域（多模态 / 图文检索） | 直接确认，结束 |
| 到一级方向（计算机视觉） | 追问一轮，收敛到子方向 |
| 只有大类（人工智能 / 计算机） | 走完整追问 |
| 完全说不清 | 先问他的兴趣来源（做过什么、看过什么、被什么吸引） |

### 第 2 步 · 出选项（核心）

**打开 `references/domain-tree.md`，从里面挑 2–4 个作为选项。**

> ⚠️ **出选项只能从 `references/domain-tree.md` 里取，不得自由造词。** 这张清单是整个追问体验的骨架——随意发挥会让产品看起来每次都在即兴表演。

如果用户的表述命中了表里的「常见叫法」，**直接映射到该节点，不要再追问**。

不要开放式地问"你想学什么"——用户说不清才来找你。给他可以点的东西：

> 多模态范围挺大的，你更想往哪个方向走？
> - 图文理解与检索（让模型看懂图和文的关系）
> - 视频与多模态生成
> - 多模态大模型微调

每个选项后面**跟一句人话解释**——用表里「一句话说明」的说法，不要丢术语给他。

### 第 3 步 · 控制轮数

**追问最多 2–3 轮。** 之后必须给判断：

> 我理解你想做的是「图文理解与检索」，对吗？

不要无限追问。用户第 4 轮就会烦。

### 第 4 步 · 收敛后落库

确定方向后：

1. 若该方向已在 `domains` 表中存在 → 直接引用其 id
2. 若不存在 → **必须先查重**（见下），命中则复用，未命中才提议新建
3. 把结果写入 `plans.target_domain`

## 新增领域节点前的四步查重（硬约束）

宁可粒度粗一点，也不要产生重复节点。

```
① 归一化      小写、去空格与标点
② 别名匹配    同时比对 name 与 aliases[]
③ 包含匹配    上下位包含关系（"多模态" ⊂ "多模态学习"）
④ AI 判定     把候选交给模型从中选，不允许自由造词
```

**前三步是确定性的，用 `scripts/dedupe.py` 跑**，不要靠感觉：

```bash
python scripts/dedupe.py --candidate "多模态学习" --domains domains.json
```

脚本会返回 `matched`（命中）或 `candidates`（待你判定的候选列表）。

**只有四步全部未命中，才提议新建。**

## 输出格式

一轮追问的输出：

```markdown
{一句话说明为什么需要收敛}

- **{选项1}**：{一句人话解释}
- **{选项2}**：{一句人话解释}
- **{选项3}**：{一句人话解释}
```

收敛结论的输出：

```markdown
我理解你想做的是「{方向}」，对吗？

选它的理由：{结合用户前面说过的话}
```

## 写入规则

- 新增/修改 `domains` 节点**必须先给草案让用户确认**，不能直接写
- 新建节点一律标 `source: ai_added`
- 领域树节点总数上限 150，接近上限时提示用户整理

## 禁止

- ❌ 开放式提问（"你想学什么方向呢？"）
- ❌ 追问超过 3 轮
- ❌ 新增节点时跳过查重
- ❌ 用户拒绝收敛时反复劝说
- ❌ 用用户听不懂的术语出选项却不解释
