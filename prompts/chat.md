# chat —— 能力一 · 方向收敛

> **对应 skill**：`domain-converge`
> **正文位置**：`prompts/system.md` → 「能力一 · 方向收敛」
> 本文件**不是待复制的正文**，而是这段能力的规格与设计说明。改提示词请改 `system.md`。

---

## 什么时候用

用户方向模糊，或只说了个大领域（"我想做人工智能""计算机""还没想好"）。

用户已经说清具体方向时**不要用**——直接确认后往下走。硬套这段能力的表现是：用户说"我想做多模态检索"，模型还在问"你想学什么方向"。

## 做法

1. **选项式追问，不要开放式提问。** 一次给 2–4 个具体方向让他挑，每个选项后跟一句人话解释。
2. 选项**只能从领域树取**（`system.md` 末尾的表格 / 专家包的 `references/domain-tree.json`），不得自己造词。
3. 追问最多 2–3 轮，之后必须给出判断："我理解你想做的是 X，对吗？"
4. 用户拒绝收敛（"我就想广泛了解"）时，给探索型路线：宽而浅，不追求深度。

## 输出形态

> 多模态范围挺大的，你更想往哪个方向走？
> - **图文理解与检索** —— 让模型看懂图和文的关系
> - **视频理解** —— 处理时间维度上的画面与文本
> - **多模态生成** —— 让模型同时生成图和文
> - **视觉语言模型微调** —— 把现成的多模态模型调到自己的任务上

## 设计理由

| 设计 | 为什么 |
|---|---|
| 选项式而非开放式 | 用户正是因为说不清才来找我们。开放式提问等于把问题原样丢回去 |
| 每个选项跟一句人话解释 | 用户不一定知道"多模态生成"是什么意思，术语裸奔等于没有选项 |
| 选项只能来自领域树 | 领域树是**单一数据源**，AI 自由造词会让第二轮的选项和第一轮对不上 |
| 最多 2–3 轮 | 无限追问会让用户失去耐心，第 3 轮必须落地成一个判断 |
| 允许拒绝收敛 | 用户有权只想广泛了解。强行收敛是把产品目标凌驾于用户意愿之上 |

## 调优方向

- [ ] 选项里的子方向目前来自领域树的 `children_hint`，还没有做查重。用户第二次进来时可能看到重复选项。
- [ ] 探索型路线目前没有专门的输出模板，模型自由发挥。
