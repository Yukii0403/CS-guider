# prompts/ —— 提示词单一事实来源

这个目录存放本产品的**全部 AI 提示词正文**。

## 为什么单独一个目录

本作品有两个交付形态：

| 交付物 | 位置 | 怎么用它 |
|---|---|---|
| 公网可对话页面 | `web-demo/worker.js` | 把对应 `.md` 的正文原样复制进 `SYSTEM_PROMPTS` |
| LearnBuddy 专家智能体 | `expert/academic-nav/skills/*/SKILL.md` | 把正文写进 SKILL.md 的指令区 |

**两个地方必须保持同一份文本。** 不允许任何一方自己另写一份——否则两周后你会发现两个版本的 AI 行为不一样，而那时已经没时间对齐了。

## 修改流程

1. 只改这里的 `.md` 文件
2. 改完立刻同步到上面两个位置
3. 改提示词属于"实质性变更"，提交信息里写清楚改了什么、为什么改

## 文件清单

| 文件 | 对应 skill | 作用 |
|---|---|---|
| `chat.md` | `domain-converge` | 通用对话与领域定位 |
| `analyze-project.md` | `analyze-project` | 从项目代码反推能力 |
| `plan-skeleton.md` | `plan-skeleton` | 生成学习计划骨架 |

## 编写约定

1. **输出格式必须写死。** 越具体的格式约束，模型越不容易跑偏。
2. **必须写清"什么时候不该用"。** 这是防止模型强行套用的关键。
3. **禁止编造事实**（论文标题、作者、链接）要显式写进规则。
4. **要求模型暴露不确定性。** 低置信度的项要单独列出让用户确认，而不是混在一起下结论。
